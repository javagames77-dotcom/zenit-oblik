# Зеніт-Авто.облік — фронт, этап 1

Три приложения на чистом HTML/JS, без сборки:

| Папка | Что это | Кто открывает |
|---|---|---|
| `admin/` | Админка: Сегодня, Отметки, Служба безопасности, Сотрудники, Филиалы и проходные, Сканеры, Отчеты | Администратор, СБ, руководители |
| `employee/` | PWA сотрудника: активация, живой QR (обновляется каждые 10 с), мои отметки, профиль | Сотрудник на своем телефоне |
| `scanner/` | PWA-сканер: камера, USB 2D-сканер, выбор события, очередь без сети, служебное меню | Планшет на проходной |
| `pass/` | Страница временного пропуска для гостя: живой QR, куда и до какого времени действует | Гость по ссылке из Viber/Telegram |
| `shared/` | Общие стили, переводы УКР/РУС, слой API, логотип, библиотеки QR | — |

## Как запустить

Камера и WebCrypto работают только по `https://` или на `localhost`, поэтому открывать через веб-сервер:

```bash
cd zenit-oblik-front
python3 -m http.server 8080
# открыть http://localhost:8080
```

Для теста с телефоном и планшетом выложите папку на любой хостинг с HTTPS (например, Render static site или nginx).

## Заглушки (режим MOCK)

В `shared/config.js` стоит `MOCK: true`. В этом режиме «сервер» живет в `shared/api.js` и хранит данные в `localStorage` браузера:

- 22 сотрудника, 5 филиалов, 6 проходных, неделя отметок;
- приглашения для активации: `Z1043A` (Пуль Олена), `Z1050A` (Федорченко Тетяна);
- код подключения сканера: `482915`; PIN служебного меню сканера: `1234`;
- вход в админку — любой логин и пароль; кнопка «Сбросить демо-данные» возвращает всё к началу.

Данные общие для всех трёх приложений только в одном браузере (одна и та же папка на одном адресе). Между разными устройствами данные не передаются — для этого нужен n8n.

Логика проверки QR в заглушке такая же, как будет на сервере: подпись HMAC-SHA256, возраст кода ≤ 45 с → `PWA_LIVE`, старше → `PWA_SCREEN`, постоянный код → `STATIC`, повтор того же кода → `REPLAY`, подделка → `INVALID`, повтор того же сотрудника на том же сканере в течение 60 с → `DUPLICATE` (не сохраняется).

## Доступы и временные пропуска

- **Права сотрудника** = свой филиал (по умолчанию) + профиль доступа + личные исключения (открыть/закрыть проходную, навсегда или до даты) − блокировка «везде».
- **Где управлять:** карточка сотрудника → вкладка «Доступ» (переключатели по проходным, видно откуда право); «Сотрудники» → отметить нескольких → «Открыть/Закрыть доступ», «Назначить профиль», «Заблокировать везде»; «Доступы» → профили и список «кто проходит» по каждой проходной.
- **Нет доступа:** отметка принимается с пометкой `NO_ACCESS`, сканер показывает красный экран, СБ получает уведомление.
- **Временный пропуск:** ФИО, компания, телефон, проходные, срок «с — по», один вход или без ограничения. Ссылка ведет на страницу `pass/` с живым QR (`TT1.P.<код>.<время>.<подпись>`). На сканере: `PASS_OK` (синий), `PASS_SCREEN` (скрин), `PASS_DENIED` с причиной (истек, не начался, отозван, не та проходная, входы исчерпаны). Гости не попадают в табель.
- Демо: в сканере кнопки «чужой филиал», «пропуск гостя», «просроченный пропуск».

## Переход на n8n

1. В `shared/config.js` поставить `MOCK: false` и указать `API_BASE` — адрес вебхуков n8n.
2. Сделать в n8n вебхуки (все `POST`, JSON, ответ JSON; токен в `Authorization: Bearer …`, сканер дополнительно шлёт `X-Device-Token`):

| Путь | Тело запроса | Ответ |
|---|---|---|
| `GET /time` | — | `{ now }` |
| `/activate` | `{ invite }` | `{ employee, qr_secret, api_token, server_time }` |
| `/me` | — (токен сотрудника) | `{ employee, last }` |
| `/my-events` | — (токен сотрудника) | `[ punch… ]` за 7 дней |
| `/device/register` | `{ code }` | `{ device_token, device, branch, gate }` |
| `/device/ping` | `{ queue, battery, version }` | `{ ok }` |
| `/scan` | `{ scan_id, qr, event, scanned_at, offline }` | `{ status, verdict, event, code_age_sec, employee }` |
| `/admin/login` | `{ user, pass }` | `{ token, name }` |
| `/admin/dashboard` | `{ branchId }` | `{ total, onSite, today, liveShare, screen, screenEmps, static, rejected, replay, feed, watch, devices, alertsOpen }` |
| `/admin/punches` | `{ from, to, branchId, verdict, q, unchecked }` | `[ punch… ]` |
| `/admin/punches/check` | `{ id }` | `{ ok }` |
| `/admin/employees` | `{ q }` | `[ employee… ]` |
| `/admin/employees/save` | `employee` | `employee` |
| `/admin/invites` | `{ empId }` | `{ code, url }` |
| `/admin/static-code` | `{ empId, reissue }` | `{ qr, version }` |
| `/admin/branches`, `/admin/branches/save`, `/admin/gates/save` | | |
| `/admin/devices`, `/admin/devices/code` | `{ gateId }` | `{ code, branch, gate }` |
| `/admin/report` | `{ from, to, branchId }` | `[ { employee, day, first, last, flags } ]` |
| `/admin/access`, `/admin/access/set`, `/admin/access/reset`, `/admin/access/profile`, `/admin/access/home`, `/admin/access/block` | см. `REAL` в `shared/api.js` | |
| `/admin/profiles`, `/admin/profiles/save`, `/admin/gates/access` | | |
| `/admin/passes`, `/admin/passes/create`, `/admin/passes/revoke` | | |
| `/pass` | `{ code }` | пропуск + секрет для живого QR |

Формы объектов (`employee`, `punch`) — как в функции `empPublic` и в записи `punches` внутри `shared/api.js`. Названия (`name`, `pos`, `branch`, `gate`) передаются объектом `{ uk, ru }`.
